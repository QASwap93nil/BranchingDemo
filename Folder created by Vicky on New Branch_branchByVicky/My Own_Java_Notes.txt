- Var (Introduced in java10)
---------------------------------->
No ❌ — `var` is NOT a primitive data type in Java. `var` is just a shortcut that tells the compiler: "You decide the data type based on the value."

	🔹 What is `var` in Java?
		`var` is **not a data type**.
		It is a **keyword used for type inference** (introduced in Java 10).
	🔹 Type inference means:
		The compiler automatically understands the data type from the value assigned.
		e.g.
				var number = 10;
			Here:
				* You wrote `var`
				* But Java automatically understands it as:
				int number = 10;
			So `number` is actually of type `int`.

	🔹 Important Rule
		`var` **must be initialized at the time of declaration**.
		e.g.	
			var x;   // Error	
			var x = 5; // correct
		Why?
		Because Java needs the value to understand the type.

	## 🔹 Important Points

	* `var` is decided at **compile time**
	* It does **not** make Java dynamically typed
	* After compilation, the variable has a fixed type
	* It works only for **local variables inside methods**
	* It cannot be used for:
	  * Method parameters
	  * Class-level variables (instance variables)
	  * Return types


	👉 `var` is **not a primitive data type**
	👉 It is a **keyword for automatic type inference**
	👉 The actual type is decided by the value assigned
	`var` = “Compiler, you choose the type for me.”

- Access Modifiers/Specifiers
------------------->
	- Access modifiers in Java are the keywords that are used for controlling the use of the constructors, fields, and methods in a class.
	- Specifies the accessibility or scope of a field, method, constructor, or class. 
	- We can change the access level of fields, constructors, methods, and class by applying the access modifier on it.
	- 4 types -> public, private, protected, default -> 
	- Access levels -> 
		✔️Private: Only within the class. It cannot be accessed from outside the class.
		✔️Default: Only within the package. It cannot be accessed from outside the package. If you do not specify any access level, it will be the default.
		✔️Protected: Within the package and outside the package through child class. If you do not make the child class, it cannot be accessed 
		  from outside the package.
		✔️Public: Access level is everywhere.
	
	-  
		Same class: -> public, protected, private, default
		Same Package : -> public, protected, default   NOT -> private 
		Outside the package in subclass(inheritance): -> public, protected -> i.e. protected can access the child classes of other packages not parent 
		classes NOT -> private, default
		Outside the package in non - subclass(non - inheritance): -> public
		
- Algorithm to Use Access Modifier in Java
-------------------------------------------->
	- Here’s a basic algorithm for using access modifiers in Java:
		- Define a class: Create a class to represent the object you want to manage.
		- Define instance variables: Inside the class, define variables for the data you want to manage.
		- Set an access modifier:
			-	Use private for variables only accessible within the class.
			-	Use protected for variables accessible within the class and its subclasses.
			-	Use public for variables accessible from anywhere.
		- Use getter and setter methods: To access or modify variables, use getter (accessor) and setter (mutator) methods, even for public variables, 
		  to maintain encapsulation.

- Java Constructor: Key Points
------------------------------->
	- Definition:
		- A constructor is a specialized method used to initialize objects in Java.
		- It is automatically called when an object of the class is created using the `new` keyword.
		- A constructor is a special feature of the class, not a class method.

	- Purpose:
		- To initialize object attributes/variables (assign initial values).
		- To set up the object's initial state.

	- Characteristics:
		- The name of the constructor **must match the class name**.
		- No return type -> (not even `void`).
		- Automatically invoked when an object is created (cannot be explicitly called).

	- Default Constructor:
		- If no constructor is defined in a class manually, the compiler provides a **default constructor** (no arguments, empty body).
		- If a constructor is explicitly defined by the programmer, the default constructor will **not** be created by the compiler.

- Types of Constructors
------------------------>
	- Default/Implicit Constructor
		- Automatically created by the compiler if no constructor is written.
		- Does not take arguments and has an empty body.
	- Explicit/Custom Constructor
		- Written by the programmer.
		- Types:
			- Non-parameterized Constructor**: Does not accept any arguments.
			- Parameterized Constructor**: Accepts parameters to initialize specific values.
			- Constructor Overloading**: Multiple constructors in a class with different parameter lists.

- Can we use access modifiers for constructors
----------------------------------------------->
	- yes we can use access modifiers to control the access by other classes
	- Access modifiers (`public`, `protected`, `default`, `private`) can control which classes can access the constructor.

- Differences Between Constructor and Method
--------------------------------------------->
	- Constructor has the **same name as the class**, while a method can have any name.
	- Constructor **does not have a return type**; methods must specify a return type.
	- Constructor is called **once** when an object is created; methods can be called multiple times.

- Rules for Constructors
-------------------------->
	- A constructor **cannot be abstract, final, static, or synchronized**.
	- It can use any access modifier (`public`, `private`, `protected`, or default).

- Constructor OVERLOADING  -> possible
--------------------------->
	- multiple constructors with same name but different parameters 
	- At COMPILE TIME, the compiler selects the appropriate constructor to execute based on the arguments 
	  provided in the new statement.

Garbage Collection and Finalize Method
------------------------------------------->
	- Java does not have a **destructor** like C++.
		- Why? 
			- Object reference variable is live till the closing curly bracket of main function. 
			- So when compiler reaches closing curly bracket, reference variable became dead. 
			- So the object in memory became referenceless. 
			- So garbage collector goes to such referenceless objects & asked them to run Finalise function(protected function).
			- When object completed the run of finalize function, garbage collector deletes the object. 
			- Hence there is no any Destructor in Java.
	- The **Garbage Collector (GC)** in Java automatically deletes objects that are no longer referenced (unreferenced/referenless).
	- When an object becomes unreachable, the garbage collector may invoke the `finalize()` method (if overridden in the class) before destroying the object.
	- **Note**: The `finalize()` method is protected and deprecated as of Java 9.
	- Java's garbage collector and `finalize()` method ensure memory management without the need for destructors.

- Constructor Inheritance
---------------------------->
	- A child class can call a parent class constructor using the super() keyword.
	- Also child has its own constructor as well(default/implicit constructor).
	- So when an object of child is made 
		a. child's constructor is called
		b. compiler goes to child's class & meet 'extends' keyword.
		c. so he find the childs constructor & add 'super()' as the first statement in child's constructor(if not explicitely added).
			- Note: if parent has default constructor & in childs constructor super() not written explicitely then Java add it & execution happens
			- Note: if the parent class has a parameterized constructor, the child class must call it explicitly using super(parameter).
		d. then he goes to parent's constructor & execute it.
		e. then came back to child's constructor & execute it.
		f. hence order of constructor calling is 1. child's constructor 2. parent's constructor.
		g. But order of execution is 1. parent's constructor then 2. child's constructor
		h. constructor calls are always top-down in inheritance, and the parent class constructor 
		   is executed before the child class constructor, ensuring that the parent class is fully initialized first.
		i. The sequence is: 1. Child constructor is called, 2. Parent constructor is executed (via super()), 3. Remaining child constructor code executes.
	4. Usage of super keyword -> IMP
		a. super can be used to refer immediate parent class instance variable. 
			- If both parent & child class has same name variable/attribute then to access the parent's variable super.variable_name is used.
		b. super can be used to invoke immediate parent class method.
			- If both parent & child class has same name method/behaviour then to access the parent's method super.method_name is used.
		c. super() can be used to invoke immediate parent class constructor.

- 'this' keyword in java:
------------------------->

	- Used to Invoke Instance Methods:  
		- `this` can be used to **call another instance method** from the current object.
	- Cannot Be Assigned:  
		- `this` is a reference and cannot be assigned a new value.
	- Used in Inner Classes:  
		- In inner classes, `this` refers to the current instance of the inner class. You can use `OuterClass.this` to refer to the outer class instance.
	- Helps with Method Overloading:  
		- `this` can be used in method overloading to explicitly invoke methods or clarify scope.
		
- 'super' keyword in java:
--------------------------->
	- `super` Keyword -> Referring to Parent Class Instance
	- Refers to Parent Class:  
		- 'super' refers to the immediate parent class and can be used to access its methods, constructors(super()), and variables.
	- Accessing Parent's Instance Variables:  
		- If the child class has the same-named variables as the parent, `super` helps refer to the parent class's instance variables to avoid ambiguity. 
	- Accessing Parent's Methods:  
		- `super` is used to invoke methods of the parent class, especially when the method is overridden in the child class.
	- Cannot be Used in Static Context:  
		- `super` cannot be used in **static methods** because static methods do not belong to a specific instance.
	- Used in Inheritance:  
		- It is mostly used when there is inheritance and the child class needs to access or modify behavior from the parent class.
		
		
- "super()" Function (Referring to Parent Class Constructor):
--------------------------------------------------------------->
	- Used to Call Parent's Constructor:
		super() invokes the parent class's constructor. This is used to initialize the parent class's state.
	- Must Be First Statement:
		super() must be the first statement in the constructor if it is called; no other statements can precede it in the child constructor.
	- Used in Constructor Chaining:
		It is commonly used to call another constructor in the parent class, enabling constructor chaining.
	- No Argument or with Arguments:
		- If the parent class has a default constructor (no arguments), super() with no arguments can be used.
		- If the parent class constructor has arguments, super(arguments) can be used to pass the required arguments.
		- If Not Called, Implicit Call:
		- If super() is not explicitly called in the child class constructor, the Java compiler automatically inserts a call to the no-argument constructor 
		  of the parent class (if it exists).
		  
- Constructor Chaining

	- Constructor chaining in Java means calling one constructor from another constructor within the same class or from a parent class. 
	- It's a way to reuse code and make sure that initialization logic happens in one place.
	- How It Works
		- In the same class: Use this() to call another constructor of the same class.
		- In the parent class: Use super() to call a constructor from the parent class.

- @Override in java
------------------------>

	- Definition
			- `@Override` is an annotation used to indicate that a method is **overriding** a method in its superclass or interface.
	- Purpose
			- Ensures that the method overrides a method from the parent class or implements an interface method.
			- Helps catch errors at compile time if the method signature doesn't match.
	- Benefits
			- Compile-Time Check**: Prevents accidental overloading instead of overriding.
			- Code Readability**: Clearly indicates that the method is overridden, improving code maintainability.
			- Error Prevention**: Detects typos or incorrect method signatures.
	- Usage
			- Placed above a method that overrides a superclass or implements an interface method.
	- Common Mistakes Detected by `@Override`
			- Mismatch in method signature
			- Attempting to override a non-existent or private method
	- Overriding Interface Methods
			- `@Override` is also used when a class implements an interface method
	- What will happen if Not Use `@Override`
			- Code will still work, but:
			- You lose compile-time checks.
			- It becomes harder to identify intentional overrides.
	- Misconceptions
			- `@Override` is optional: It's not required for overriding but is a best practice.
			- Does not affect runtime behavior: It is only a compile-time annotation.

class Process1 implements Runnable{
	public void run(){   // as Program 1 & program 2 are implementing Runnable interface we need to do method overriding of run(), else both program will be abstract
		for(int i=1; i<=10; i++) System.out.println("Process1 'i' is: " + i);
	}
}

class Process2 implements Runnable{
	public void run(){
		for(int i=11; i<=20; i++) System.out.println("Process2 'i' is: " + i);
	}
}

class MultiThreading1{
	public static void main(String args[]){
		Process1 p1 = new Process1();
		Process2 p2 = new Process2();
		
		// Thread class implements the Runnable interface & Runnable has only one method run(). So to execute run method need to create a thread object
		// But when object is created the constructor of thread also executes & this constructor accept only runnable type data. Hence Process 1 & process 2
		// are implementing the runnable interface.
		Thread t1 = new Thread(p1);
		Thread t2 = new Thread(p2);
		t1.start(); // When `t1.start()` is called, it begins executing the `run()` method of `Process1` in a separate thread.
		t2.start();
	}
}

/* Step by step explaination
--------------------------------->
	- What is a Thread?
		- A thread is like a separate path of execution in a program. It allows your program to do multiple things at the same time (concurrent execution). 
		- For example, if your program is like a road, then threads are like separate lanes on that road, allowing multiple cars (tasks) to move 
		  simultaneously without waiting for each other.
	- One Thread in the Given Program:
		- In your program, `t1` is a thread.
			- What is `t1`?**
			- `t1` is a thread created using the `Thread` class.
			- It is responsible for running the task defined in `Process1`.
		- What does `t1` do?**
			- When `t1.start()` is called, it begins executing the `run()` method of `Process1` in a separate thread.
			- The task of `t1` is to print numbers from 1 to 10.

	- Step-by-Step Simplest View:
			- Process1 p1 = new Process1();`  
				- Creates the task that will print numbers 1 to 10.
			- Thread t1 = new Thread(p1);`  
				- Wraps the task (`p1`) into a thread (`t1`), so it can run concurrently.
			- `t1.start();`  
				- Starts the thread, making it execute the `run()` method of `Process1`.

	- What Happens When You Run the Program?
			- `t1` and `t2` start running at the same time.
			- `t1` prints numbers from 1 to 10.
			- `t2` (another thread) prints numbers from 11 to 20.
			- Both threads run independently and may interleave their outputs.
*/

	}

---------------------->

   - Example:

- File
---------------->
	- A file is a container in a computer system used to store and organize data in a structured format. 
	- Files allow us to save data PERMANENTLY (until explicitly deleted) so that it can be accessed, modified, or shared later. -> Saved in ROM.
	- Types of Files:
		- Text File: Stores readable text data (e.g., .txt, .csv).
		- Binary File: Stores non-readable data like images, videos, or executable programs (e.g., .exe, .png).
	- Structure of a File:
		A file consists of:
			- Header: Metadata about the file (e.g., file size, creation date, type).
			- Data: The main content of the file, either text or binary.
			- Footer: Optional additional information or markers.

- File Handling in programming
-------------------------------->
	- Refers to the process of creating, opening, reading, writing, and managing files on a computer. 
	- It allows programs to interact with files to store or retrieve data for future use.
	- 3 Logical Operations in file handling
		- Opening a file    -> Take file into RAM from HDD(ROM)
		- Processing a file ->
		- Closing a file    -> Save the file in the HDD
	- Basic Operations in File Handling:
		- Create a File: Make a new file on your system.
		- Open a File: Access an existing file to read, write, or update it.
		- Read from a File: Retrieve data stored in the file.
		- Write to a File: Save data into the file.
		- Close a File: Finish working with the file and release system resources.

- 'File' class
-------------->
	- 'File' Class in Java:
		- The `File` class is used to represent the metadata of a file or directory in the file system (not the file content itself).  
		- Metadata -> file name, path, size, permissions, and existence.  
	- File Object in RAM:
		- When you create a `File` object (e.g., `File f1 = new File("path_to_file");`), the program stores a "reference to the file's metadata" in memory (RAM).  
		- This object does "not create or open the file". 
		- It simply creates a reference to the file's location in the storage (ROM or disk).
	- How to Create a `File` Object:
		- File f1 = new File("path_of_file_in_storage");
		- If the file already exists, the `File` object will reference it.
		- If the file does not exist, you can create it using the `createNewFile()` method.
	- Breakdown of File f1 = new File("path_of_file_in_storage");
		- What does the File object contain?
			- The File object in the heap contains:
				- The metadata of the file (e.g., name, path, size, etc.).
				- A reference (internally managed by the JVM) pointing to the file's location in storage (ROM or disk).
		- What does f1 store?
			- The reference variable f1 in the stack memory stores the memory address of the File object in the heap.
	- Hence the File object does not represent the actual file content but only acts as a bridge to interact with the file on disk.

- Methods of 'File' class
------------------------------>

		- Creates a new, empty file if it doesn’t already exist.

		- Returns the path (relative or absolute) used to create the `File` object.

		- Returns the absolute path of the file.

		- Returns the length (size) of the file in bytes.  
	- `isFile()`

import java.util.Stack;

public class StackDemo {
    public static void main(String[] args) {
        // Create a Stack to store Strings
        Stack<String> stack = new Stack<>();

        // Push elements onto the Stack
        stack.push("Alice");
        stack.push("Bob");
        stack.push("Charlie");

        // Print the Stack
        System.out.println("Stack: " + stack);

        // Peek the top element (without removing it)
        System.out.println("Top element: " + stack.peek());  // Charlie

        // Pop elements from the Stack
        System.out.println("Popped element: " + stack.pop()); // Charlie
        System.out.println("Popped element: " + stack.pop()); // Bob

        // Check if the Stack is empty
        System.out.println("Is stack empty? " + stack.isEmpty());  // false

        // Print the remaining elements
        System.out.println("Remaining stack: " + stack);

        // Pop the last element
        System.out.println("Popped element: " + stack.pop()); // Alice

        // Check if the Stack is empty
        System.out.println("Is stack empty? " + stack.isEmpty());  // true
    }
}

--------------

- - Time Complexity
	- Descending order
		O(N^3) > O(N^2) > O(N) > O(Log(N)) > O(Nlog(N)) > O(1)
	- The time complexities 
		- **O(N^3)**: Cubic time complexity, grows very fast with large inputs.
		- **O(N^2)**: Quadratic time complexity, commonly seen in algorithms like bubble sort or matrix multiplication.
		- **O(N)**: Linear time complexity, grows directly in proportion to the size of the input.
		- **O(Log(N))**: Logarithmic time complexity, common in algorithms like binary search where each step reduces the problem size exponentially.
		- **O(Nlog(N))**: Log-linear time complexity, typically seen in efficient sorting algorithms like Merge Sort and Quick Sort.
		- **O(1)**: Constant time complexity, the fastest, where the operation doesn't depend on the size of the input.

public class SortedInterface {

	- Definition: A `HashSet` class is part of the Java Collections Framework and implements the `Set` interface. It is backed by a hash table 
		(actually a `HashMap` instance).
	- Uniqueness: It does not allow duplicate elements. Any duplicate insertion is ignored.
	- Order: It does not guarantee any specific order of the elements (not sorted). 
	- Null Elements: It allows a single `null` element.
	- Performance:
		- Time Complexity: O(1) for basic operations like `add()`, `remove()`, and `contains()` on average. Uses hash codes for storing elements.
		- Hashing: Uses hash codes for storing elements.
	- Thread-Safety: It is not synchronized. If thread-safety is required, you can use `Collections.synchronizedSet()` or `CopyOnWriteArraySet`.
	- Common Methods:
		- `boolean add(E e)`: Adds an element.
		- `boolean remove(Object o)`: Removes the specified element.
		- `boolean contains(Object o)`: Checks if an element exists.
		- `int size()`: Returns the number of elements.
		- `boolean isEmpty()`: Checks if the set is empty.
		- `void clear()`: Removes all elements.
	- Constructor: 
		- `HashSet<E>()`: Default constructor.
		- `HashSet<E>(Collection<? extends E> c)`: Initializes the set with elements from another collection.
		- `HashSet<E>(int initialCapacity)`: Initializes with a specific capacity.
		- `HashSet<E>(int initialCapacity, float loadFactor)`: Initializes with a specific capacity and load factor.
	- Default capacity is 16
	- When filled 75% grows dynamically(double like vector) (Load factor 75% -> can be changed)


- A 'HashSet' is like a box where you can keep items, but:
	- Each item must be **unique** (no duplicates allowed).
	- The box doesn't care about the order of items.
	- For example:

		HashSet<String> set = new HashSet<>();
		set.add("Apple");
		set.add("Banana");
		set.add("Apple"); // Duplicate, so it's ignored.
		System.out.println(set); // Output: [Apple, Banana]

	- Does it store key-value pairs?**
		- No! A **HashSet** stores only **values** (like "Apple", "Banana").
		- If you want to store key-value pairs (like "Name = John"), you need to use a **HashMap** instead.

- Example of HashSet:
-------------------------

	import java.util.HashSet;

	public class HashSetDemo {
    public static void main(String[] args) {
        // Create a HashSet
        HashSet<String> fruits = new HashSet<>();

        // Add elements to the HashSet
        fruits.add("Apple");
        fruits.add("Banana");
        fruits.add("Orange");
        fruits.add("Apple"); // Duplicate, won't be added

        // Print the HashSet
        System.out.println(fruits); // Output might look like: [Banana, Orange, Apple]

        // Check if an element exists
        if (fruits.contains("Banana")) {
            System.out.println("Banana is in the HashSet!");
        }

        // Remove an element
        fruits.remove("Orange");

        // Print the updated HashSet
        System.out.println(fruits); // Output might look like: [Banana, Apple]
    }
	}


- LinkedHashSetDemo
------------------------>
	- child class of HashSet
	- HashSet & Doubly linked list both are used here
		- Uses a hash table to store elements for fast access (like HashSet).
		- Uses a doubly linked list to maintain the insertion order of elements.
	- Insertion order preserved.
		- Unlike HashSet, which does not guarantee any order, LinkedHashSet maintains the order in which elements are added.
	- Used hybrid datastructure
	
	- Key Differences Between `HashSet` and `LinkedHashSet`:
	
| Feature               | `HashSet`                  | `LinkedHashSet`           |
|-----------------------|----------------------------|---------------------------|
| Order of Elements**   | Unordered                  | Preserves insertion order |
| Performance**         | Faster (no order tracking) | Slightly slower (due to linked list) |
| Use Case**            | When order doesn't matter  | When order is important    |

	- Constructors:
		- LinkedHashSet<E>(): Default constructor.
		- LinkedHashSet<E>(int initialCapacity): Initializes with a specific capacity.
		- LinkedHashSet<E>(int initialCapacity, float loadFactor): Initializes with a specific capacity and load factor.
		- LinkedHashSet<E>(Collection<? extends E> c): Initializes with elements from another collection.
	
	- Common Methods:
		- boolean add(E e): Adds an element.
		- boolean remove(Object o): Removes the specified element.
		- boolean contains(Object o): Checks if an element exists.
		- int size(): Returns the number of elements.
		- boolean isEmpty(): Checks if the set is empty.
		- void clear(): Removes all elements. 
	
- Example of LinkedHashSet:
-----------------------------

	import java.util.LinkedHashSet;
	public class LinkedHashSetDemo {
    public static void main(String[] args) {
        LinkedHashSet<String> set = new LinkedHashSet<>();

        // Add elements
        set.add("Apple");
        set.add("Banana");
        set.add("Orange");

        // Common methods
        System.out.println("Set: " + set);                     // [Apple, Banana, Orange]
        System.out.println("Size: " + set.size());             // 3
        System.out.println("Contains 'Banana': " + set.contains("Banana")); // true
        System.out.println("Is Empty: " + set.isEmpty());      // false

        set.remove("Orange");
        System.out.println("After removing 'Orange': " + set); // [Apple, Banana]

        set.clear();
        System.out.println("After clearing: " + set);          // []
    }
	}

Lecture21: ->  Cursors | Enumeration | Iterator | ListIterator in Java
--------------

- Cursors
----------------->
	- Simply pointers 
	- Dont confuse with 'Cursor' class: Cursor class is a part of Java AWT package and it is used to create custom cursors 
	  or inherit system or predefined cursors.
	- Generally used to retrieve the data from collection object one by one.
	- There are 3 cursors in java
		- Enumeration
			- It is an Interface in java
			- Only available for legacy classes in all collection framework: Hence only usefull for Vector & Stack.
			- has two abstract methods
				- boolean hasMoreElements();
				- E nextElement();
			- Vectors & stack has a function called 'elements()' which returns the Enumeration(Enum) type data.
				- e.g. v1 is an vector object then v1.elements() will return an Enumeration type data. Hence need to store it in Enumeration variable
				- This 'elements()' function is only usefull for enumartion
				- Enumeration is not the same as 'enum' keyword in Java.
					- enum is a keyword in Java used to define a special class with constant values.
					- It is a type-safe way to define a set of predefined constants.
					- Can have methods, constructors, and variables.
					- Used for categorizing fixed values like days of the week, colors, etc.
					- Example program
						enum Color {
							RED, GREEN, BLUE;
						}

						public class EnumExample {
							public static void main(String[] args) {
								Color c = Color.RED;
								System.out.println(c);  // RED
							}
						}
		- Enumeration can move in single(forward) direction only.
		- Only Read option is available.
		
		- Iterator
			- It is also an Interface in java.
			- Has three abstract classes
				- public boolean hasNext();
				- public E next();
				- public void remove();
			- How it is different from Enum?
				- Is available for Collection implemented classes.
				- Hence all classes have 'iterator()' function.
				- it just not the retrieve the data but can remove the data as well. (Enum can only retrive the data)
			- Iterator can move in single(forward) direction only.
			- Only Read & Remove option is available.
			- Both Enumeration and Iterator do not have any parent interface. They are independent interfaces used for traversing collections.
		
		- ListIterator
			- It is child interface of 'Iterator' interface
			- ListIterator is bi-directional cursor.
			- Also available for all List implemented classes with name 'listIterator()'.
			- Has seven abstract classes
				- public boolean hasNext();
				- public E next();
				- public void remove();
				- public boolean hasPrevious();
				- public E previous();
				- public void add(E e);
				- public void set(E e);  // replaces
				- public int nextIndex();
				- public int previousIndex();

- Example Program
----------------------

import java.util.*;

class CursorsDemo{
	public static void main(String args[]){
		Vector v1 = new Vector();
		v1.add('A');
		v1.add('B');
		v1.add('C');
		v1.add('D');
		v1.add('E');
		v1.add('Z');
		
		// Enum
		Enumeration e1 = v1.elements();
		System.out.println("Following is the output of Enum");
		while(e1.hasMoreElements()){
			System.out.println(e1.nextElement());
		}
		System.out.println("-------------------------------");
		
		// Iterator
		Iterator i1 = v1.iterator();
		System.out.println("Following is the output of Iterator");
		while(i1.hasNext()){
			char char1 = (char)i1.next();
			if(char1 == 'C')
				i1.remove();
			else	
				System.out.println(char1);
		}
		System.out.println("-------------------------------");
		
		// ListIterator
		ListIterator l1 = v1.listIterator();
		System.out.println("Following is the output of ListIterator \n");
		System.out.println("//Forward");
		while(l1.hasNext()){
			System.out.println(l1.next());
		}
		System.out.println("//Backward");
		while(l1.hasPrevious()){
			System.out.println(l1.previous());
		}
	}
}

Lecture22: ->  Difference between HashMap & Hashtable 
--------------

In Java, Hashtable and HashMap are both implementations of the `Map` interface, used for storing key-value pairs. However, they have key differences:

| Feature               | **Hashtable** | **HashMap** |
|-----------------------|--------------------------------------|------------------------------------------------------|
| **Thread Safety**     | Synchronized (thread-safe)           | Not synchronized (not thread-safe)                   |
| **Performance**       | Slower due to synchronization        | Faster as it is unsynchronized                       |
| **Null Keys/Values**  | Does not allow `null` keys or values | Allows one `null` key and multiple `null` values     |
| **Legacy vs. Modern** | Legacy class (part of Java 1.0)      | Introduced in Java 1.2, preferred for new development |
| **Iteration (Fail-Fast vs. Fail-Safe)** | Fail-Safe (does not throw `ConcurrentModificationException`) | Fail-Fast (throws `ConcurrentModificationException` if modified during iteration) |
| **Use Case**          | Used in multi-threaded environments requiring synchronization | Used in single-threaded or externally synchronized environments |

-  When to Use What?
	- Use **Hashtable** if you need built-in synchronization.
	- Use **HashMap** for better performance in single-threaded applications or use `Collections.synchronizedMap(new HashMap<>())` for thread safety.

- Object Oriented Programming:
	- Object-Centric Approach – In OOP, everything revolves around objects, which represent real-world entities.
	- Encapsulation of Data & Behavior – Objects encapsulate both data (attributes) and methods (operations) that manipulate that data.
	- Functions are member of class(static) or object(instance). Hence they can not be stored in an variable as value/data.
	- In traditional Object-Oriented Programming (OOP), functions (or methods) are typically bound to objects and cannot be passed directly as arguments.
		- Here data is passed as an argument
		- In pure OOP, methods are bound to objects and cannot be passed directly.
	- However, in modern Java (from Java 8 onwards), you can pass functions as arguments using functional interfaces, lambda expressions, and method references.
	- Functional Interfaces: Templates for function, making it easier to use them in different parts of your program.
	- e.g.
		1. Using Functional Interfaces (Lambda Expression)
			- Java provides predefined functional interfaces such as Function<T, R>, Predicate<T>, and Consumer<T>.
				import java.util.function.Function;
				public class FunctionAsArgument {
					// Method that takes a function as an argument
						static int operate(int x, Function<Integer, Integer> function) {
							return function.apply(x);
						}
						
					public static void main(String[] args) {
					// Passing a lambda function
					int result = operate(5, num -> num * num);  // Square function
					System.out.println(result); // Output: 25
					}
				}
				
		2. Using Method References : Instead of lambdas, you can pass method references directly:
				public class MethodReferenceExample {
					static int square(int x) {
						return x * x;
					}

					public static void main(String[] args) {
					// Passing a method reference
					Function<Integer, Integer> squareFunction = MethodReferenceExample::square;
        
					// Using the function
					System.out.println(squareFunction.apply(6)); // Output: 36
					}
				}


	
	
- Functional programming:
	- Way of writing program in which functions are treated as small building blocks of code.
	- functions are the primary building blocks, and computations are treated as evaluations of mathematical functions. 
	- functions are treated as data (can be stored in variable) & passed as an argument or return a function.
	- It focuses on immutability, pure functions, and declarative code rather than object manipulation. -> Ask for more elaborate ans
	- Function-Centric Approach
		- Unlike OOP, where objects are central, FP revolves around pure functions (functions without side effects).
		- Operations revolve around function composition, higher-order functions, and immutability.
	- Pure Functions:-> A function is considered pure if:
		- It always returns the same output for the same input.
		- It has no side effects (does not modify external state).
	- Immutability
		- Data is not modified; instead, new copies are created.
		- Example using Java Streams (Functional Style)
			List<Integer> numbers = List.of(1, 2, 3, 4, 5);
			List<Integer> squaredNumbers = 	 numbers.stream()
											.map(n -> n * n) // Transformation without modifying original list
											.toList();
	- Higher-Order Functions
		- Functions can be passed as arguments or returned from other functions.
		- Functions can be stored in variable
		- Example (Java Function Interface)
			Function<Integer, Integer> square = x -> x * x; // Function as a variable
			System.out.println(square.apply(5)); // Output: 25	
	- Declarative Programming
		- Instead of how to do something, FP focuses on what to do.
		- Example
			// Imperative (OOP Style)
				List<String> names = new ArrayList<>();
				for (String name : List.of("Alice", "Bob", "Charlie")) {
					if (name.startsWith("A")) {
					names.add(name);
					}
				}

			// Functional (FP Style)
				List<String> names = List.of("Alice", "Bob", "Charlie")
                         .stream()
                         .filter(name -> name.startsWith("A"))
                         .toList();

- Lambda Expression
-----------------------
	- nameless/anonymous functions (like arrow functions in JS)
	- Syntax: 
		- if there are multiple parameters & multiline code: (parameters) -> {code;}
		- if there is single parameter & single line of code: parameter -> code;
		- if there is no parameter: () -> code;  OR ()->{Multi line code;}
		- in multiline if lambda expression is returning something then write return explicitely.
	- Try to avoid multiline code in lambda expression
	- Great with collections
	- Can be use in functional interface only i.e. used to implement a method of a functional interface


- Java Stream
-----------------------
	- Sequence of elements (we dont know where is the end, so do operation on it parallely)
	- Streams dont store the data
	- They just on the fly process the data from collection or arrays.
	- Useful for doing functional operations (like filter, map, reduce)
	- In built multi threading support
	- Intermediate operations returns the stream
	- Terminal operations don't return anything.
	- hence if there is no terminal operation is used, need to store in stream variable.
	- if used terminal operation, do not store it as it consumes the stream.


- Filter & reduce
---------------------
	- Filter(Intermediate Operation)	
	  -----------------------------
		- Purpose: 
			- Used to filter elements of stream.
			- Only those emelents passed the given condition(predicate) are included to result stream.
		- Lazy Operation:
			- Not executed until a terminal operation is invoked on the stream
		- Returns a stream:
			- Filter method returns a stream of elements which passed the condition.
		- E.g.
			List<String> lt = List.of("Apple", "Banana", "Kiwi", "Pineapple", "Pomegranate", "Date", "Papaya");
			// convert the collection to stram using stream() method
			lt.stream().filter(e -> e.endsWith("e")).forEach(e -> System.out.println(e));
			
	- Reduce(Terminal Operation)
	  ---------------------------
		- Purpose:
			- Used to reduce the elements of stream to a single value.
			- can be used for summing, finding min/max or other oprrations
			- e.g.1 // return the sum of all elements
			List<Integer> numbers = List.of                        
			numbers.stream()
					.reduce(0, (a,b) -> a+b;)	// 0 is the initial return.
			
			- e.g.2 // return the max of all elements
			List<Integer> numbers = List.of(1,2,3,7,8,9,11,45,12);
			numbers.stream()
					.reduce(Integer.MIN_VALUE, (a,b) -> a>b ? a : b);  // use of ternery operator
